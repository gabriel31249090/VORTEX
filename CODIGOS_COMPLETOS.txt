## 1. Infraestrutura Base (já existente)

- App Router do Next.js 16, com middleware de autenticação (redireciona pra `/login` se não logado)
- ~18 rotas prontas: login/register, feed (geral/seguindo), busca, criação de post, visualização de post, notificações, perfil, comunidades, salvos, settings, pricing
- Nav responsiva: sidebar no desktop, bottom bar no mobile
- Editor de posts com upload de imagem, vídeo, áudio e GIF

## 4. Sistema de Anúncios (Bloco B)

**Status: ✅ Estrutura implementada**

- Tabela `ads` no Supabase (título, descrição, imagem, link, tipo `popup`/`feed`, ativo) com RLS: admins têm controle total, usuários veem apenas anúncios ativos
- Regras definidas:
  - Pop-up ao abrir o site, com cooldown (1x por sessão)
  - Anúncio no feed a cada **40 posts**
  - Formatos aceitos: texto+link e imagem+link
- Componentes criados: `AdPopup.tsx` e `FeedAd.tsx`
- Aba de Anúncios adicionada ao painel `/admin` (criar, editar, ativar/pausar, deletar)
- **Pendente:** integrar `FeedAd` no `app/feed/page.tsx` (lógica de inserção a cada 40 posts) e `AdPopup` no `app/layout.tsx` (exibição global)

## 6. Novo Projeto: Integração de Jogos (Abismo das Fichas + Ficha D&D + VoidOS)

**Status: 🟡 Em planejamento, primeira etapa iniciada**

Ideia geral: trazer os jogos/ferramentas standalone para dentro do próprio Vortex, como uma seção de jogos.

### Decisões já tomadas
1. Tudo vai viver **dentro do Vortex** (não em site separado)
2. Abismo das Fichas vai virar **multiplayer em tempo real** entre usuários do Vortex (via Supabase Realtime)
3. Ficha de D&D será **simplificada** e usada como sistema de criação de personagem no Abismo
4. Do VoidOS: aproveitar **animações/efeitos visuais** e o **terminal**, traduzido para português e simplificado

### Ordem de ataque definida
1. Ficha de personagem simplificada (base do sistema)
2. Jogo Abismo integrado ao Vortex usando a ficha
3. Multiplayer via Supabase Realtime
4. Terminal do VoidOS como feature extra

### Progresso técnico
- Tabela `characters` desenhada (nome, raça, classe, nível, XP, HP, CA, velocidade, os 6 atributos — FOR/DES/CON/INT/SAB/CAR, skills e inventário em JSONB, notas, avatar) com RLS completo (usuário só vê/edita/deleta os próprios personagens)
- Decidido criar um **bucket próprio no Supabase Storage** chamado `characters` (público) para os avatares dos personagens
- **Próximo passo:** confirmar criação do bucket → rodar o SQL da tabela `characters` → começar o código da ficha
